Why the old VLM bars appeared to overlap AE GPU execution:
The old plot in essay/figures/plot_paper_figures.py painted the full wall-clock
interval [kernel.start_us, kernel.end_us] as a continuous bar, even when that
interval included paused_us. This was a plotting error, not evidence that
AE and VLM GPU execution overlapped in the simulation.

Checked native scheduling behavior:
experiments/2026-11-16/source/ramulator2/src/ramulator/frontend/impl/pim_vla_frontend.cpp
- When AE needs the GPU, VLM moves from running to draining at a checkpoint.
- Accepted memory requests drain before the state changes to paused.
- AE GPU work starts only when there is no active VLM kernel or VLM is paused.
- VLM resumes after AE GPU work; pause duration is accumulated in paused_us.
Both cases use vlm_gpu_quantum_us = 2. This is a modeled yield boundary, not
an independently measured Thor preemption mechanism or measured handoff cost.
